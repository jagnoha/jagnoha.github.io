AgentForge

A private engineering CLI that turns bounded agent attempts into inspectable evidence while keeping validation, human approval, and GitHub publication behind explicit boundaries.

A guarded path from task to draft pull request.

02 / Engineering architecture

Evidence crosses boundaries; authority does not.

The local CLI coordinates policy and durable state around an owned Git worktree. Agent execution is bounded, validation is revision-specific, and GitHub mutation remains outside the run until approval is verified.

SQLite stores tasks, attempts, events, checks, review packages, approvals, and publication records so recovery does not depend on an agent’s final message.

03 / Engineering highlights

Reliability designed around exact evidence.

A successful process exit is only one event. The system preserves the stronger proof needed for review, approval, and recovery.

01Featured control

Human authorization binds the exact publication snapshot

The approval challenge is separate from execution and review. Changed credentials, repository state, metadata, or review artifacts invalidate the publication path.

02

Guarded lifecycle

Policy prevents generic status changes from skipping required validation, review, or approval evidence.

03

Revision-bound validation

Trusted profiles, ordered checks, and before-and-after fingerprints keep passing results attached to the revision that produced them.

04

Fail-closed recovery

Timeouts, cancellations, stale claims, and uncertain remote outcomes enter explicit recovery paths instead of being treated as success.

05

Constrained publication

Deterministic commit construction and same-repository branch controls limit GitHub writes to an approved draft pull request.

04 / Technical challenges

Design decisions at trust boundaries.

  • Execution is not validationA zero exit code and final message do not create test evidence or approve a revision.
  • Validation is not authorizationPassing checks can make a revision reviewable, but cannot permit remote mutation.
  • Approval is snapshot-specificThe publication gate rechecks the evidence and identity attached to the approved candidate.
  • Timeout is ambiguousA timed-out push or PR request is reconciled before any retry to avoid duplicate or conflicting writes.
  • Local does not mean unguardedWorktree containment, credential boundaries, durable claims, and bounded repair reduce accidental repository damage.
