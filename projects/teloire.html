02 / Engineering architecture

Canonical writes drive rebuildable experiences.

Next.js clients call a domain-oriented NestJS API. PostgreSQL owns listings, availability, reservations, quotes, orders, and financial records; no search index, cache, browser state, or payment response can redefine that truth.

Transactional outbox workers project listing changes into discovery and run other asynchronous consumers. Stripe calls stay outside database transactions and return trusted evidence for idempotent finalization.

03 / Engineering highlights

Commerce state stays authoritative under concurrency.

The implementation favors explicit ownership, durable events, and reversible projections over coupling product truth to a provider or cache.

01Featured workflow

Inventory first. Provider calls second.

Checkout locks items in deterministic order, persists a reservation and server-owned quote, calls Stripe outside the transaction, then revalidates trusted payment evidence before atomically creating order truth.

02

Stable discovery sessions

Resolved intent and ordered results are snapshotted so cursor pages do not silently reparse or reorder a query.

03

Version-aware projections

Transactional outbox events and version checks prevent delayed asynchronous work from overwriting newer listing state.

05

04 / Technical challenges

Decisions that protect marketplace truth.

  • Canonical versus derived dataPostgreSQL owns business facts; search projections, sessions, Redis controls, and provider responses remain replaceable.
  • Inventory concurrencyDeterministic row locking and expiring reservations prevent two buyers from completing the same item.
  • Payment isolationExternal calls stay outside database transactions, while idempotent finalization consumes trusted evidence exactly once.
  • Search eligibilityExplicit category, size, condition, price, and availability constraints remain hard gates before ranking.
  • Seller importsExternal seller-platform imports are planned, not verified as implemented; the current evidence supports seller-created canonical listings and APIs.

Pre-launch development status

Implemented work includes canonical listings, outbox processing, deterministic search and private sessions, reservation concurrency, authoritative quotes, and idempotent order finalization. Optional AI enrichment is experimental. Production provider activation, managed infrastructure, monitoring, backup/PITR, external seller imports, and business, legal, and tax launch decisions remain incomplete.
